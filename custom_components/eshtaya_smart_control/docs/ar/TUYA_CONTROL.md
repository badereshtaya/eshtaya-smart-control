# إدارة تويا

## مبدأ الإصدار 2
تويا قسم اختياري بالكامل. تثبيت Eshtaya Smart Control لا يطلب أي معلومات تويا. عند فتح «إدارة تويا» لأول مرة يظهر نموذج التفعيل، وبعد فحص الاتصال وحفظه تتحول الصفحة إلى مساحة إدارة الأجهزة.

## البيانات المطلوبة
- مركز البيانات/Region.
- معرّف العميل (Client ID / Access ID).
- سر العميل (Client Secret / Access Secret).
- معرّف المستخدم UID.
- رابط API مخصص فقط عند اختيار Custom.

## التفعيل لأول مرة
1. افتح Eshtaya Smart Control ← إدارة تويا.
2. اختر مركز البيانات المطابق لمشروع Tuya IoT.
3. أدخل معرّف العميل والسر وUID.
4. اضغط «فحص الاتصال».
5. راجع عدد الأجهزة والرابط الذي تم اختباره.
6. اضغط «تفعيل الحساب». لا يتم اعتماد بيانات فاشلة.

## تعديل الحساب
من إعدادات الحساب يمكنك تغيير Region أو Client ID أو UID أو تدوير السر. السر الحالي لا يعرض للمتصفح. عند السماح بترك خانة السر فارغة يتم الاحتفاظ بالقيمة الحالية.

## إلغاء التفعيل
يحذف فقط حقول تويا من Config Entry الموحدة. إدارة الكيانات وMulti-Way والمجموعات الذكية تبقى كما هي.

## الأجهزة
القسم يدعم البحث بالاسم والمعرّف والتصنيف والمنتج، فلترة متصل/غير متصل، pagination وتحديث كامل. هناك Cache قصير في الباك إند لتقليل الضغط على OpenAPI.

## تفاصيل الجهاز
حسب ما توفره Tuya: Device ID وUUID وProduct ID والتصنيف ومعلومات IP وShadow Properties.

## تغيير الاسم الرئيسي
يتم التعديل على Tuya Cloud نفسها وليس Friendly Name محلي فقط.

## أسماء المخارج
يمكن تعديل `custom_name` للأكواد المدعومة التي ترجع فعلياً من Shadow Properties مثل `switch_1` و`socket_1` و`control`. النظام لا يخترع أكواداً غير موجودة.

## التعديل الجماعي
يحمّل خصائص الأجهزة بتزامن محدود ثم يحفظ التعديلات. راجع كل تغيير لأن العملية تعدل Metadata سحابية حقيقية.

## الأمان
Client Secret والتوكنات تبقى في الباك إند، التوقيع HMAC-SHA256 يتم داخل Home Assistant، ولا ترجع الأسرار في Status أو تقارير الدعم.

## أشهر الأخطاء
فشل الاتصال: راجع Region والصلاحيات والاشتراكات والبيانات وUID. قائمة فارغة: راجع ربط UID بالمشروع. رفض التسمية: قد لا يسمح الجهاز أو الصلاحية أو الـProperty بهذه العملية.
